## データソース仕様

### e-Stat API

| 項目 | 内容 |
|------|------|
| エンドポイント | `https://api.e-stat.go.jp/rest/3.0/app/json/getStatsData` |
| 認証 | APIキー（無料登録で取得） |
| 取得指標 | CPI・GDP・完全失業率 |
| データ形式 | JSON |
| 更新頻度 | 月次（CPI・失業率）、四半期（GDP） |

### 日本銀行 時系列統計 API

| 項目 | 内容 |
|------|------|
| エンドポイント | `https://www.stat-search.boj.or.jp/api/` |
| 認証 | 不要（公開API） |
| 取得指標 | マネーサプライ（M2）・政策金利・円ドル為替レート |
| データ形式 | JSON / CSV |
| 更新頻度 | 月次 |

### 内閣府 需給ギャップ

| 項目 | 内容 |
|------|------|
| 取得方法 | ファイルダウンロード（CSV または Excel） |
| 認証 | 不要 |
| データ形式 | CSV または Excel（実装前に内閣府サイトで要確認） |
| 更新頻度 | 四半期 |

## データベース設計方針

### 2層アーキテクチャ

```
raw 層（生データ）
  └─ APIから取得したデータをそのまま保存
  └─ 削除・上書きしない（追記のみ）
  └─ 再加工の起点として機能

mart 層（加工済みデータ）
  └─ raw 層から変換・集計したデータ
  └─ ダッシュボードが直接参照する層
  └─ パイプライン実行のたびに再構築可能
```

### DuckDB 採用理由

- サーバーレスで動作し、インストール・運用が不要
- pandas との親和性が高い（DataFrame の直接読み書き）
- 分析クエリ（集計・ウィンドウ関数）が高速
- 単一ファイル（`data/macro.db`）で管理が容易

## パフォーマンス要件と対策

| 要件 | 目標値 | 対策 |
|------|--------|------|
| ダッシュボード初期表示 | 5秒以内 | mart 層を事前集計済みにし、起動時クエリを最小化 |
| パイプライン実行時間 | 制限なし（バッチ処理） | 差分更新で不要なAPI呼び出しを抑制 |
| データ取得失敗時 | 既存データで継続表示 | コレクターの例外を捕捉しパイプラインを継続 |

## セキュリティ要件

| 項目 | 方針 |
|------|------|
| APIキー管理 | `.env` ファイルで管理し、`.gitignore` でリポジトリ除外 |
| APIキー共有 | `.env.example` にキー名のみ記載してテンプレートとして共有 |
| 外部通信 | データ取得時のみ（ダッシュボード表示はローカルDB参照） |
| 入力バリデーション | API レスポンスのスキーマ検証を各コレクターで実施 |

## 技術的制約

| 制約 | 内容 |
|------|------|
| 動作環境 | devcontainer（Docker）上のみをサポート |
| オフライン動作 | データ取得済みであればインターネット接続なしで閲覧可能 |
| データ保持 | 生データ（raw 層）は削除しない。ストレージ上限なし |
| 外部サービス依存 | e-Stat API・日本銀行 API の仕様変更でコレクターの修正が必要になる場合がある |
| スクレイピング回避 | サイト構造変更への耐性を高めるため、スクレイピングは原則使用しない |
